# Wrenfield Credit Opportunities: findings

Fictional credit hedge fund (four books, 150 bonds, 40 CDS, USD and EUR, 103 business days) adopting the platform on
AWS. "Measured" means a test or a run in this folder shows it (`tests/mock_funds/test_wrenfield*.py`); "inferred" means
read from code or docs, not run. Nothing outside `examples/mock-funds/wrenfield/` and `tests/mock_funds/` was changed.

Dialect differences met between DuckDB, SQLite (the stand-in), and PostgreSQL:
- Dates: the lake gives a `DATE` from the hive key `dt` (formatted with `strftime`); SQLite holds text; PostgreSQL holds `date`. The OMS SQL uses `CAST(date AS TEXT)`, the common subset; DuckDB needs `strftime`.
- Parameters: `:book` for SQLite, `%(book)s` for psycopg, none in DuckDB (the path is substituted into the text). A small `_named` converts them.
- Identifiers: all lower case, so PostgreSQL's folding did not bite; a vendor warehouse with quoted mixed-case names would.
- Three-part names: the OMS is `oms.pos_eod` on PostgreSQL and `pos_eod` in SQLite; the connection sets `search_path=oms` so the SQL stays unqualified. In Athena the names would be `wrenfield_curated.bond_px_daily`, and DuckDB reads Parquet by path, with no catalog.
- Partition pruning: expressed in the path glob in DuckDB, in `WHERE dt = ...` in Athena and Redshift Spectrum. Not expressible from a dataset id, which has no date range.
- Numeric types: `numeric(18,2)` returns `Decimal` from psycopg; SQLite and DuckDB return floats. The pivot converts with `float`.

## Not tested

Run against real PostgreSQL, S3, Athena, Cognito, or ECS: none. The Postgres path, DDL, CloudFormation, and task definition were written and cross-checked against the code but never executed. Items marked inferred are from reading code and docs.

## Top generic improvements, in order

1. JWT verification by JWKS in the sign-in file (C1, C2, C3, C5): every cloud identity provider issues signed JWTs; only Cognito's missing `aud` and opaque `sub` need two more settings.
2. Per-column and per-row access rules (15, 16): this fund cannot enforce a wall without them, and duplicates 14 datasets without them.
3. Credit analytics in Quant Toolbox (1, 2, 3, 5, 6): carry and roll attribution, DTS, CS01, JTD, basis, scenario stress, and financing in backtests.
4. A SQL and object-store `DatasetStore` with a declarative spec (C14, C16, Data connection): about two thirds of the fund's store code is generic.
5. Scale limits and evidence size (11, 10): per-column evidence and per-column warnings make 1,500 bonds a blocker.
