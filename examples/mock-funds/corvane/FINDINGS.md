# Corvane Equity Partners: findings

Fund: a benchmark-aware, long-only equity manager (two strategies, five accounts, 401 securities, 110
business days) on S3 + Snowflake + Cognito + ECS Fargate. Evidence is marked **measured** (I ran it and
saw the output; the test that shows it is in `tests/mock_funds/test_corvane.py`) or **inferred** (read from
code or docs, or reasoned, not run). All sizes are for this estate (generation 0.6 s, 1.9 MB, 21 tests in
about 12 s).

## 2. Cloud

| # | Area | What happened (evidence) | Severity | Generic platform fix suggested | Fund-specific or generic |

| C1 | Sign-in vs Cognito | A Cognito user pool has no RFC 7662 endpoint. `IntrospectionVerifier` pointed at the pool's `/oauth2/introspect` gets 404 and returns None for every token (only a logged warning). Nothing in the platform validates a JWT against a JWKS. (measured) | blocker | A JWKS/OIDC verifier beside introspection: signature (RS256), `iss`, `exp`, `aud` or client id, key rotation by `kid` | Generic |
| C2 | Workaround | I wrote `corvane_introspect.py` (80 lines, a Lambda behind API Gateway or a sidecar): it checks the RS256 signature against the pool's JWKS and answers in introspection shape, adding `aud`, mapping scopes, and rejecting ID tokens, forged signatures, and expired tokens. The platform's verifier then works end to end. It adds a network hop per uncached token (cache 60 s) and a service to run. (measured) | major | As C1 | Generic |
| C3 | Claims | Cognito access tokens have no `aud`, and the verifier requires the resource URL in it; `scope` is `qaos/tools.call`, not `tools:call` (scopes would be empty without mapping); `cognito:groups` works as `groups_claim` (colon accepted); `tenant_claim = ""` works for one pinned tenant. | C5 | Identity Center | IAM Identity Center is not modelled; it issues OIDC tokens through an application, with group membership not in the token by default (needs a SCIM-synced directory call). (inferred) | minor | Document it | Generic |

## 4. Data connection (the store, for the shared connector)

`site/corvane_store.py`, 348 lines, counting non-blank non-comment lines:

| Part | Lines | What it is | Generic? |
| --- | --- | --- | --- |
| Header (docstring, imports, constants) | 48 | | partly |
| Connection | 85 | `SqlConnection` protocol (6), `connect()` from one URL and env secrets (22), the Snowflake branch (30), the offline DuckDB stand-in (about 40, only for tests) | Generic: protocol, URL and secret references, the connect branch. The offline stand-in is test scaffolding |
| Query and mapping | 96 | `Entry` (id prefix, SQL, index name, bind, fill) and 13 entries; bound parameter lists | Generic: `Entry` and the id-to-SQL registry. The SQL text is the fund's |
| Pivot and shape | 21 | long rows (index, column, value) to a wide CSV with a fill value | Generic |
| Caching | about 12 | TTL cache and a lock | Generic |
| Fingerprint and version | 0 | none: `parse_dataset` hashes the CSV | Already platform |
| The SQL | 113 (views) + 80 (Snowflake setup) | calendar, life of a security, USD returns, carried closes, daily holdings weights, drifted benchmark weights, ADV, point-in-time scores | Fund's own. The patterns (calendar join, as-of carry, drift) are generic |

No per-dataset Python logic: every dataset is an `Entry`. The one thing that is not declarative is deriving
account and benchmark ids from the database (`BINDINGS`, three queries).

**Would a generic SQL-backed `DatasetStore` have replaced my adapter?** For about 160 of 348 lines (the
protocol, `connect`, `Entry`, the registry, the pivot, and the cache), yes: "one query per dataset id, long
rows pivoted to wide" is exactly this store. It would not replace the 113 lines of views, which is where the
fund's conventions live (USD returns on closed days, drifted benchmark weights, point-in-time scores). It
needs, beyond the brief's shape: bound parameters per id template (`weights_{account}`); a fill value per
dataset (weights are 0 where absent, returns are NaN); an id list that can come from a query; a string index;
and a `?`/`%s` placeholder setting. It also would not make datasets with string columns work (finding 8).

## 5. `qaos legacy scan` on `facility/legacy/corvane_quant`

Output: `7 callables: 0 expose, 5 facade, 2 service`.

| `attribution.run` | service: no hints, pandas data, prints, `global LAST_RESULT`; "named like an entry point; left out" | Service is right (global state), but "left out" drops the one function the fund runs every month, because it is called `run` |

Nothing classified as `expose`: every function lacked type hints or used pandas. Generic fix: treat
attribute assignment on an imported module as state; do not drop an entry point by its name alone.

## 6. What the platform lacks for benchmark-relative work (summary)

Benchmark-relative statistics exist only at whole-sample level; nothing about holdings, benchmark
constituents, groups, attribution, active share, ex-ante risk, corporate actions, calendars, point-in-time
data, or categorical reference data. The analytics tools take series and frames of numbers. For a manager
whose job is relative to an index, the fund's own tools (section 1, row 1) are most of what it uses daily.
